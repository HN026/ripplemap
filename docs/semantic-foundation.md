# Milestone 1: semantic foundation

## Outcome

**Passed:** separate producer and consumer SCIP indexes join using the complete
symbol string. An aliased call resolves to the producer definition. The other
consumer and a local same-named function do not match. No source-text search is
used to establish identity.

## Fixture and provenance

The sources are in `fixtures/semantic/`. The library exports `removed` and
`retained`. `removed-consumer` imports `removed as renamed`, calls `renamed`, and
also defines and calls an unrelated local `removed`. `retained-consumer` imports
and calls only `retained`.

The checked-in `index.scip` files were generated by the unmodified npm-distributed
`@sourcegraph/scip-typescript` **0.6.2**, using TypeScript **6.0.3**, Node
**24.22.2**, and npm **11.12.1** on macOS. Tool dependencies and workspace package
identities are captured in `package-lock.json`. Compilation and index generation
succeeded on 2026-11-11; the decoded results were verified at
**2026-11-11T17:43:32Z**. This is provenance for this manual acceptance run, not an
indexer-provided timestamp or a repository commit field.

The binary files are the actual indexer outputs, totaling 3,770 bytes. They have
not been rewritten or synthesized. SHA-256 digests:

| Package | SHA-256 |
| --- | --- |
| library | `2bb389412f83571b1e6b19eb63e9b9d6d99f7983c02e39998124972e7eddaa77` |
| removed-consumer | `1ddb1aee5847859e1c03e58d1b005f1986b75f28722f1adc59c10d823bdd6b44` |
| retained-consumer | `9afeda1ad55d3f866c6a70a265f0ec332f04764454f6bb4ae2bc635db2adb542` |

Each file includes `metadata.tool_info` naming the indexer and version, and an
absolute `file://` project root from the generation machine. Regeneration at a
different checkout path changes that metadata and therefore the binary digest;
the semantic assertions should still pass. The documents use relative paths.
SCIP metadata here carries neither an exact Git commit nor a successful-index
timestamp. Ingestion must require those explicitly in Milestone 2.

Exact installation, compilation, indexing, and checking commands are in the
[README](../README.md). `scripts/check-semantic.mjs` decodes with the indexer's
SCIP bindings and asserts the observations below; it is fixture tooling, not the
future product implementation.

## Observed identity and package version

Producer definition and all three consumer occurrences carry this exact string:

```text
scip-typescript npm @ripplemap/library 1.0.0 src/`index.ts`/removed().
```

The components encode scheme `scip-typescript`, package manager `npm`, package
name `@ripplemap/library`, exact version `1.0.0`, and descriptors for the source
file and function. Backticks escape the filename descriptor. The full string is
the join key; no suffix, spelling, alias text, or version-stripping is needed.
A query for the otherwise identical `2.0.0` identity returns no references in
this fixture. That assertion proves exact comparison, not real cross-version
resolution (no version-2 package was indexed).

The local same-named function has this different identity:

```text
scip-typescript npm @ripplemap/removed-consumer 1.0.0 src/`index.ts`/removed().
```

Its definition and call join to each other, but never to the producer symbol.

## Occurrences, aliases, and positions

All document paths below are `src/index.ts`, relative to each indexed root.
These documents declare `position_encoding = 2` (UTF-16 code units). Ranges
are zero-based, end-exclusive; a three-element range means
`[line, start_character, end_character]` on one line. General SCIP also supports
four-element ranges. The ASCII fixture does not test astral Unicode conversion.

| Index | Occurrence | Raw range | Display start (line:column) | Roles |
| --- | --- | --- | --- | --- |
| library | `removed` definition | `[0,16,23]` | 1:17 | 1 |
| library | `retained` definition | `[4,16,24]` | 5:17 | 1 |
| removed-consumer | imported `removed` | `[0,9,16]` | 1:10 | 0 |
| removed-consumer | alias binding `renamed` | `[0,20,27]` | 1:21 | 0 |
| removed-consumer | call `renamed(1)` | `[2,22,29]` | 3:23 | 0 |
| removed-consumer | local `removed` definition | `[4,9,16]` | 5:10 | 1 |
| removed-consumer | local `removed(2)` call | `[7,25,32]` | 8:26 | 0 |
| retained-consumer | imported `retained` | `[0,9,17]` | 1:10 | 0 |
| retained-consumer | call `retained(1)` | `[2,22,30]` | 3:23 | 0 |

`symbol_roles` is a bitset; bit 1 marks definitions. These references have roles
0, including import occurrences: the indexer did not set the Import bit here.
The alias has no separate symbol or relationship to chase in this fixture; its
binding and use already carry the producer's exact identity. An import and its
alias produce two occurrences on the same line. The result is **three reference
locations in one affected consumer**, not three calls or three affected repos.

## External symbols and limits

All three `external_symbols` lists are empty. Consumer `documents[].symbols`
contain only their own symbols; producer definitions are absent there. Yet
consumer occurrences encode full identities for the dependency functions and
module. Thus an empty external-symbol table does not imply unresolved imports.
The producer index supplies the corresponding definition.

This validates source-distributed workspace packages with a direct TypeScript
entry point. Published declaration files, export aliases/re-exports, overloads,
dynamic access, unresolved dependencies, and other package layouts remain
unverified. In particular, declaration-file paths may differ from producer source
paths: do not assume those identities join until a later fixture proves it.
These indexes do not establish which definitions are public exports, complete
consumer coverage, or runtime call behavior. No public-export diff, ingestion,
impact command, Rust implementation, or compatibility claim is included yet.
